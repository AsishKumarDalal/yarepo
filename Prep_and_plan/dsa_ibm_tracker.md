## 🧭 What IBM Actually Tests (from candidate reports)

- **Online Assessment:** 2 coding problems on HackerRank, about 50 to 70 minutes, easy to medium, array and string heavy. An English assessment follows. Some campus drives add a group discussion.
- **Reported question styles:** arrays, palindrome and reverse-string, binary search, bubble sort explanation, target sum, kth max using a priority queue, permutations, tree questions, and cutting time/space of a brute-force answer.
- **Interview:** resume projects first, then OOPs, DBMS (keys, SQL queries), basic DSA, and call by value vs reference. Low-CGPA questions have been reported, so have a confident answer ready.
- **Takeaway:** IBM leans easy to medium. Depth on arrays, strings, hashing, binary search, linked lists, trees, and clean C++ beats grinding hard graph/DP problems. Treat Hard problems as optional.

> Source patterns come from Glassdoor candidate reviews and placement sites such as PrepInsta. Formats change by year, so use this as a map, not a script.

## ⚙️ Working Rules

1. Time-box: 20 min thinking, then read hints, then re-code from memory next day.
2. Say the brute force and its complexity out loud before coding. IBM interviewers ask you to improve it.
3. Dry-run on 2 small inputs and 1 edge case (empty, single element, duplicates, negatives).
4. Re-solve any problem you needed help on after 3 days.
5. Do the IBM-Reported Set twice.

**C++ reminders:** `vector`, `unordered_map`, `priority_queue` (min-heap: `greater<int>`), `sort` with lambdas, `string` vs `char` handling, use `long long` when sums can overflow, pass big containers by reference.
